# Protocol v2 evidence record, 2026-11-01

This record covers the `feat/protocol-v2` branch on the published Ratify
Protocol `2.0.0b1` packages. It is local evidence: nothing here was run
against Maritime, the public console, or the scenario proxy, and no image was
published. The Protocol v1 deployment evidence in this directory
(`adversarial-results.json`, `runtime-isolation-results.json`, and the dated
sections of `docs/EVIDENCE-MATRIX.md`) is unchanged and remains the record of
the live pilot, which still runs Protocol v1. The earlier pre-release record,
[`protocol-v2-2026-10-22.md`](protocol-v2-2026-10-22.md), is kept as dated
history.

## Limits

- The claim store, receipt log, checkpoint, issuance store and security
  journal are the SDK's in-memory reference stores. They are not durable and
  the checkpoint runs in the receiver's process, so it is not an independent
  failure domain. This is a demonstration verifier, not a production-shaped
  one.
- The single-device offline profile (SPEC-v2 §7.13) does not apply to this
  connected hosted receiver and is not claimed.
- A signed status list is current for at most one day, so a v2 deployment
  needs a daily status signing step. Writing the list to the receiver's
  volume is not yet automated by `rotate_deployment_authority.py`.
- `2.0.0b1` is a prerelease. Review so far is the protocol project's own
  pre-release security review; external independent review is a gate for
  `2.0.0`.
- No v2 deployment, live gate, Maritime review, or published image exists.
  This reference is not described as v2-compatible on the strength of this
  record alone.
